# team_memory — 팀 공유 메모리 (선택 층)

개인 `memory/` 가 "나 혼자의 규칙"이라면, `team_memory/` 는 **팀 전체가 공유하는 규칙**입니다.
혼자 쓸 때는 필요 없습니다. 여러 명이 같은 하네스를 쓰기 시작하면 이 층을 켜세요.
(책 4부 "팀에서 AI가 사고 치지 않게 하는 법", 5부 "도입만 하고 끝난 AI를 다시 쓰게 만들기"에 해당하는 실물)

## 개인 memory 와 무엇이 다른가

| | `memory/` (개인) | `team_memory/` (팀) |
|---|---|---|
| 누가 고치나 | 나 혼자 | **회고에서 합의한 뒤에만** |
| 적용 범위 | 나 | 팀 전원 |
| 예시 | 내 답변 취향 | 커밋 메시지 규칙, 용어집 |

## 구조

```
team_memory/
├─ README.md            ← (이 파일)
├─ users.md             ← 팀원 ↔ 작업 공간 매핑
├─ shared/              ← 팀 전원 공통 규칙 (직접 수정 금지 · 합의 후만)
│  ├─ commit_rules.md
│  ├─ workflows.md
│  └─ conventions.md
├─ atoms/               ← 팀 공유 메모리 (개인 memory 와 같은 포맷, 자동 주입됨)
│  ├─ rules/ decisions/
│  └─ (색인은 memory/_jit_manifest.json 에 함께 생성)
└─ <이름>/              ← 팀원별 개인 공간 (협업 스타일 · 메모 · 회고)
   ├─ context.md        ← 이 사람과 일할 때의 스타일
   ├─ notes.md          ← 개인 작업 메모
   └─ retro/
```

## 두 가지 원칙 (팀으로 쓸 때)

1. **`shared/` 직접 수정 금지** — 팀 공통 규칙은 회고에서 합의한 뒤에만 바꾼다.
   한 사람이 조용히 바꾸면 나머지가 모른다.
2. **남의 폴더는 읽기만** — `<이름>/` 안은 그 사람 것. 참고는 하되 고치지 않는다.

## 훅과의 연결

`team_memory/atoms/` 의 메모리도 개인 `memory/` 와 **똑같이 자동 주입**됩니다.
`scripts/build_manifest.py` 가 두 곳을 함께 스캔해 하나의 색인을 만들기 때문입니다.
팀 규칙은 보통 개인 규칙보다 우선하므로 `score` 를 조금 높게 둡니다.
